## 2026-10-11 Owner 修订 / RD-007

来源：[外审关键摘录与 Owner 原话“认同”](governance/sources/2026-10-11-owner-discovery-review.md)。接受 RB-DISC-001 的 Discovery 交付，下一阶段方案按本节修订，原报告保留为历史评审版本。

1. 采用 Discovery → Greybox → Visual 三门；Garage POC 仅检验空间、表现与操作，不能证明玩家爱上玛丽、车已成为家或完整继续旅行意愿。
2. 当前 POC 使用 Godot + Windows + 键盘；不是产品技术锁定。
3. C 首先做 C0 Spatial Spike，只验证空间/操控五个问题；C1 Narrative Greybox 与 Visual 要分别审查，不批准 30h 总包。
4. OD-015 替代旧“三种都做同一可玩成品”的要求：A/C 有体验假设；B 需独立艺术/体验主张后才可申请实施；C 先试不等于胜出。
5. 剧情表记录作者希望的经历，不是交互锁顺序。提前发动、先看其他部位等合理行为原则上允许；硬限制必须是世界物理原因。
6. 数字是异常信号，不是内容目标；不要求识别两件家庭痕迹，不为通过比例而增加大标识/字幕提示。记录自然行动、感受、复述与误解。
7. C1 核心检验人物戏：无面捕/脸部特写，仅用站位、身体动作、停顿、声音与有限镜头，让母亲的意图/情绪可读。

补充保护：仅看见损伤不改变机械状态，不得以 damage_seen 解锁发动；第一发动失败只是候选世界反应，不能规定每次必演。C1 局部人物戏可读不证明完整家庭情感；完整情感需要适当前置关系，当前不因此开发完整序章或锁定前置时长。

正式决定 DEC-OPI-1093f782-2177-4d58-bd83-d665a81d9772.2（契约 revision 2）；C0 PLAN/TASK 见 [binding](governance/binding.json)。原建库 DEC/PLAN/TASK 保留，不覆写历史。新决定只替代本节指出的实施要求，其余 OD 继续有效。此为 RD-007 登记时的状态：方向已批准，C0 执行准入当时未成立；旧报告专属 READY 不可复用。当前执行依据见 RD-008 与 CURRENT。

## 2026-10-11 Owner 执行 / RD-008

来源：[第三轮外审及 Owner 原话“执行”](governance/sources/2026-10-11-owner-c0-execution.md)。保留 RD-007 的阶段与验证边界，仅进一步收缩 C0：

1. 当前只有一次进入玛丽驾驶；不做下车、重复上下车、车外落点或墙边下车验证。
2. 车库门打开后保持打开，不实现关闭或 toggle。为避免先上车形成死路，车外/驾驶态均可使用同一个就近开门占位交互；不据此确认遥控装置等剧情设定。
3. 同场景只比较即时响应与轻微加减速/有限转向两组局部参数，观察起步、转向、停车。禁止扩建车辆物理模块。
4. 检查位置仅作空间参照；不需要确认热点、计数或操作前置。只评构图、尺度、至少两个侧面的环绕、单次进入驾驶、低速离库。
5. Owner 授权先完成本轮必需的正规 PROTOTYPE 执行依据，再制作最小灰盒；不改文档 Discovery 历史，不造 FINDING/override，不扩展 C1。

## 2026-10-11 Owner 阶段接受 / RD-009

来源：[外审、核对分析与 Owner 原话“认同”](governance/sources/2026-10-11-owner-c0-close-c1a.md)。

1. 接受 C0 当前探索交付并关闭此阶段，冻结六个工程文件。驾驶/碰撞已有实际反馈；构图、尺度、环绕、首次进入驾驶四项未记录完整主观定性，如实保留。阶段接受不是五项全部客观验证，也不是最终 3D 决定。
2. 玛丽重量感当前适合来自缓起步、有限转向、体积与空间压力；松键即停、撞墙不滑移保留为候选经验，不因大质量重新默认滑行。
3. 下一步只授权 C1-A First Meeting：实体门逐渐显露玛丽、两个人同场、自由绕车、母亲一个动作/停顿、一件自然观察细节、极少候选短文本或沉默、玩家首次主动触碰；到此结束。
4. C0 是冻结实验材料，不是 C1 代码底座。另按剧情组织最低人形灰盒与场景内有限构图，不做 CameraManager/长对白/正式资产/多个热点；动作/文本候选不写成正式设定。
5. 玩家先触碰、走任一侧、忽略细节、往返/离开均允许；不以观看顺序锁操作。Profile 1/2 不进入 C1-A。
6. C1-B 的异常、启动、母亲参与与驶出以后另裁；本轮不做 A/B 可玩或 Visual。只验证局部人物戏，不证明完整家庭情感。
7. 同一 prototype_execution@1 用新决定/PLAN/TASK、精确路径与固定进程另取 READY；不修改上游协议。C1-A 无真实人工接受保持 VERIFYING。

正式 DEC DEC-OPI-50e5092d-5afe-478d-b0d0-9a465c8d3605.2@2、C1-A PLAN/TASK@1 见 [binding](governance/binding.json)。C0 原生 TASK 没有 DONE 生命周期接口，本地阶段关闭由本次真实 Owner DEC 记录，不伪称原生 TASK 已改 DONE。
