## 3. 只锁体验，不锁正式对白

共同七段：进入 → 开门 → 看见玛丽 → 接近检查 → 发现异常 → 与母亲发动 → 玩家驶出。开门是空间动作，不增加钥匙/背包/门控系统。结束只到门外短距离，不接全序章、标题、公路地图或战斗。

| 节拍 | 玩家欲望/行为 | 信息变化 | 最小表现 |
|---|---|---|---|
| 进入/开门 | 想知道地下室还剩什么；走下、开门 | 长期未进入的空间 | 连续入口或一次有方向感过渡 |
| 首见 | 认出旧车；走近、绕看 | 先旧，再熟悉 | 车体尺度/磨损、两处家庭痕迹；极短取景后还控制 |
| 检查 | 确认还能否用；看损伤/痕迹 | 父亲走前有明确损伤 | 近距离检查点，不打开性能页 |
| 异常 | 分辨哪里不对；对照 | 变化不可能由普通修补解释 | 一条短记忆信息与局部现状，不解释真相 |
| 发动 | 让母亲与车一起上路；明确动作 | 旧机器开始回应 | 输入→母亲有限动作→机械反馈→可驾驶 |
| 驶出 | 自己把大车开过门口 | 玛丽确实能继续前进 | 短距离低速、碰撞反馈、稳定镜头和结束点 |

主角记得旧损伤，不知道变化原因。母亲有家庭关系，不做世界观解说；她是否认识异常未设定，不添加她其实知道的秘密。父亲缺席但痕迹存在，不加幽灵/闪回或死亡解释。两处痕迹候选粗焊与旧座椅，具体内容待 Owner 决定；不锁车型/轮履/年龄。暗红锈蚀/新生金属仍只是表现候选。

片段本地状态最多记录门开、首见完成、损伤已看、启动状态、控制对象和结束，防重复触发即可；不抽象 QuestService/world_state。无持久化，重玩回初态。普通说话仍可移动/观察，走开后再接近可读必要信息，不强制跳剧情。

## 4. A/B/C 最小技术方案与目录

技术建议：优先用已有 Godot 经验评估一个小 POC 工程，容纳独立路线入口，不造模式选择器。旧 Godot 4.7.1 是历史经验，**不是新版本锁**。具体稳定版本、渲染后端和试验机器须审查后记录；本轮没有安装/运行引擎或核实 API 兼容性。Windows/键盘是首轮试验平台提案，手柄和发行平台不锁。

| 项目 | A Pixel 2D | B Hybrid 2.5D | C Stylized 3D |
|---|---|---|---|
| 空间/首见 | 斜俯视或侧向二维车库，门后轮廓完整可读 | 3D 车库/玛丽，2D 人物置于空间 | 3D blockout 空间/玛丽/人物，固定或半固定构图 |
| 移动/镜头 | 平面移动/边界碰撞；固定或小范围跟随 | 平面约束的 3D 移动，固定镜头朝向，有限人物朝向 | 约束移动，2–3 个明确镜头区域；禁止自由旋转 |
| 检查/异常 | 局部观察视图，旧裂口与候选异常两层可辨 | 近景/3D 损伤贴片，人物不抢信息 | 受限靠近/局部近景；贴片而非全局腐败 shader 系统 |
| 母亲/文字 | 极少帧动作/短字幕，站位承担关系 | 少量 sprite 朝向/动作，脚底、阴影、遮挡成立 | capsule 占位，后续少量身体动作，无面捕 |
| 发动 | 振动/灯/声音响应与控制对象切换 | 车体反馈，人物退出驾驶路径 | 同左，近距离反应强化体积 |
| 驶出 | 慢速二维运动、门宽/碰撞，无完整履带物理 | 粗碰撞体低速运动，人物与门框深度排序 | 受控车体运动/碰撞滑动，无完整悬挂/轮胎模拟 |
| 最少新建 | 片段场景、局部移动/车/交互脚本、短文本表 | 片段场景/本地脚本、sprite 站位规则、短文本表 | 片段场景/本地脚本、镜头区域、短文本表 |
| 最大风险 | 重量/小家庭痕迹读不清，近景需重画 | 光照/遮挡/朝向/落地与双管线成本 | 遮挡、门宽/转弯、尺度、人物动作成本 |

不在此锁最终 API/类名；实现时用真实输入与生命周期验证，不以实例化替代运行。无装备页、开放世界、完整动画库、写实角色、AAA 精度、完整车物理或改装。不得引用 Legacy DriveSimulator/VehicleRuntime。

目录仅为提案，本轮不创建；一个获批工程先只出现获批的第一条 Greybox，其他路线仍是文本：

- `pocs/project.godot`：唯一试验配置，版本获审后锁定。
- `pocs/pixel_2d/garage_poc.tscn`、`pocs/hybrid_2_5d/garage_poc.tscn`、`pocs/stylized_3d/garage_poc.tscn`：独立入口；每个获批路线约 3–5 个本地脚本。
- 路线下 `assets/`：获准后才创建，明确占位/试验/正式的区别。
- `pocs/content/garage_texts.json`：若确实需要，仅共用短文本/信息点，无注册器。
- `docs/discovery/`：本报告；未来证据按获批工单留存，不预建记录系统。

不建 src/features 分层、全局 service/autoload、EventBus、存档/任务/库存/UI 框架或 launcher。共享信息清单与输入约定即可，强行共用 2D/3D 控制器会掩盖实际成本。

## 6. 资产与制作工作量（待审）

Greybox 仅方块家/车库、capsule 或色块人物、粗车体/门/损伤色块、两处痕迹占位。**不生成漂亮的玛丽，不建正式资产库。** 占位反馈验证检查与启动，情绪到 Visual 才判断。

Visual 共用信息需求：极简家入口/车库、主角/母亲、一辆玛丽、门、旧损伤/变化局部、两处家庭痕迹、一小组雨声/机械启动反馈。不是整镇、武器/部件/车队清单。残缺旧歌仍为候选，本轮不作曲、不采购、不采用受版权保护歌曲。

| 路线 | Greybox 输入 | Visual 追加资产/工作 | 主要返工风险 |
|---|---|---|---|
| A | 二维几何、人物/车色块、粗门/检查点 | 单角度空间背景，玛丽少量启动帧，人物少量方向/动作，损伤/痕迹近景 | 尺度改变需重画，痕迹太小迫使过多文字 |
| B | 低模空间/车体、平面人物占位 | 风格化空间/车体、2D 人物少量动作/朝向、贴片，混合阴影与透明排序 | 镜头改变重做朝向与遮挡，双管线维护 |
| C | 粗 3D 空间/车体、capsule 人物 | 空间/车体风格化材质磨损、两位低复杂度人物/少量动作、局部异常 | 镜头未成立前细化导致模型/动画返工 |

AI 概念/基础网格/预演、Blender 清理、shader 试验仅是将来工具候选，不代表采购/插件批准。采用前记录工具版本、费用、输入、使用权与许可证；统一比例、造型、材质、配色、年代、磨损、腐败和技术规格，人工调整审查。不因漂亮而准入正式资产，不复制旧美术当成品。

估算：一位熟悉引擎的通才，人日 = 6 小时实际制作；含基本运行检查与一次修改。排除学习、采购/工具试错、插件、发行包装、多平台、招募等待。**误差至少 ±50%，不是承诺。**

| 路线 | Greybox 人日/工时 | Visual 追加人日/工时 | 说明 |
|---|---|---|---|
| A | 3–4 / 18–24h | 5–8 / 30–48h | 原创像素细节/近景需人力，2D 不天然便宜 |
| B | 4–6 / 24–36h | 8–13 / 48–78h | 混合表示调试成本较高，避免全套双管线 |
| C | 3–5 / 18–30h | 8–12 / 48–72h | 早测体积，人物/材质统一成本留到后门 |

建议先审一个 **C Greybox 风险试验**，上限 30h，测镜头、遮挡、门宽与低速驾驶；依据 OD-016 的验证优先，不等于艺术获胜或 C 已证明更好。Owner 可选 A 先行，B 双管线风险可在空间控制成立后测。每条 Greybox 独立审查，不自动给三条全部预算。

Visual 对等预算提案：每路线最多 60h。A 不把剩余额度转成额外剧情；B/C 可能超限，须提前呈现缺项/风险，Owner 统一延长或缩减共同内容，不能排序完成度不同的版本。记录真实工时/返工，不用生成时间代替全部资产成本。
