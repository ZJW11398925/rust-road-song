# Legacy 重新准入规则 / P0约束的执行细则

版本：0.1；依据 OD-001..003、OD-018。**默认不复用。旧代码是重新申请进入，不是迁移。**

## 旧库的身份

Legacy 保留实现、测试、设计和历史，是技术资产库。它不能约束新的产品、剧情、视觉、UI 标杆、服务边界、槽位数量、任务路线或存档格式。
旧测试证明旧设计认真执行，不证明旧设计值得继续。不得把旧测试数量作为新项目质量目标。定位及冻结基线见 [Legacy](../references/LEGACY.md)。

## 申请条件

先回答：“当前已确定的玩家体验为什么需要它？”答案指向当前已批准片段和玩家行为。
申请必须列当前任务、最小用量、源提交及文件、依赖闭包、为什么不能更少、需要删掉的旧假设、版本/许可证、验证方法、回滚、Owner 决定及 DMCP 引用。
没有当前消费者或会拖入冻结系统，直接拒绝。不得整个 src/、addons/、content/ 或治理目录复制。

## 初始判断（是边界，不是复用批准）

| 候选 | 当前处理 | 理由 |
|---|---|---|
| QuestService | 不进入 | 六步片段不需要完整任务模型 |
| WorldService及三个世界数值 | 不进入 | 新设计不接受原抽象为前提 |
| BountyDirector/赏金 | 不进入 | 无当前玩家需求 |
| 旧装备、经济、营地、多车、职业 | 不进入 | 范围冻结 |
| 完整存档系统 | 不进入 | 当前实验可重置；持久化必要性以后再证明 |
| 输入系统 | 只评估最小输入与失焦经验 | 实验需要控制，不因此迁移设备/重映射框架 |
| Localization | 可评估少量文本资源 | 很可能需要，不自动批准旧模块 |
| 测试框架/验证思想 | 可评估最小工具 | 有意义的错误/真实输入/试玩经验保留，不搬整个套件 |
| 旧美术/音频 | 默认不进入 | 年代、比例、风格、磨损与权限需重新审核 |

## 准入流程

五项需求说明 → 当前体验证明 → 最小文件/依赖评估 → Owner 审查 → 正式决定与任务依据 → 有边界引入 → 本次验证。每项单独登记；批准本地化不能顺带批准注册表、存档、QuestService。
本轮复用数为零：不复制旧游戏代码、资产、插件或测试。治理工具消费来自独立 DMCP 工具链，不来自 Legacy 游戏工程。
