## PLAYER NEED

玩家要走近并绕车，进入玛丽驾驶，从狭窄门口低速驶出。当前只需要单次进入，不需要下车；空间/输入若妨碍这些动作，后续表达无从成立。

## NARRATIVE / GAMEPLAY CONTEXT

无人物戏的地下车库空间试验。不含母亲、信、异常、家庭物件、正式对白或资产；不验证情感、不批准 C1。

## MINIMUM IMPLEMENTATION

一个 Godot 4.7.1 灰盒入口、局部静态类型脚本、真实碰撞与受约束镜头。路径为 pocs/stylized_3d/c0/ 下 project.godot、garage.tscn、garage.gd、spatial_smoke.gd、strings.tres、README.md；报告 docs/pocs/RB-C0-001_REPORT.md。

WASD 移动/驾驶；E 就近开门或进入驾驶；R 重置；1/2 从相同初态比较即时起停与缓起步/松键即停/有限转向；Esc 退出。门打开后保持打开。车外与驾驶态使用同一占位开门交互，避免提前上车形成死路；不是剧情遥控装置。一个空间参照位置，不设检查解锁/热点清单。初次被动减速滑行受到Owner实玩反馈，当前停车改为松键即停，原始反馈与实验修订见报告。起步、转向、停车只用局部参数，不建车辆物理模块。

## WHY NOT LESS

静态图无法揭露移动方向、遮挡、门槛、控制切换与起停感。方块与胶囊足够，不需要未来下车、关门、物理模拟或叙事资产。

## LEGACY DEPENDENCY

NONE；仅借输入/失焦经验，不复制旧工程、框架、插件、资产或测试套件。

## 五个问题与证据

1. 构图：移动中能否稳定看清车、人、出口。
2. 尺度：接近时大型机器的体积是否可信。
3. 环绕：两个不同侧面是否可自然到达，是否持续与遮挡/输入搏斗。
4. 进入驾驶：只测一次车外→驾驶，不丢输入/镜头/空间。
5. 离库：极低速狭窄出口中起步/转向/停车是否产生重量且能控制。

正式准入后，相关 L1/L2、L3、L4 正式入口真实生命周期/映射键盘事件验证；记录远处反馈、墙/闭门碰撞、提前进入驾驶、开门一次、重置和失焦。错误日志为失败证据，退出码 0 不足。自动注入键盘事件与物理键盘人工操作分列；真实运行录像/截图只能辅助，不代替 L5。
