# RB-C0-001：C0 Spatial Spike 工单与最小实施计划

状态：方向已批准；正式 PLAN/TASK 已登记；代码执行准入未成立，尚未实施。依据 RD-007；引用见 [binding](../governance/binding.json)。

Goal：只回答镜头看车、接近尺度、绕车检查、控制切换、低速驶出五个问题。
Architecture：一个独立 Godot 灰盒场景与局部控制脚本；局部信号/直接调用足够，不建设通用服务、事件总线或任务状态。
Tech Stack：Godot + Windows + 键盘；具体可用版本在准入/实施前核实并记录，不锁定产品技术。

## PLAYER NEED

玩家需要看清、走近并绕过车体，切换控制后亲自从门中驶出。若镜头或控制阻碍这些自然动作，玛丽的后续表达无从成立。

## NARRATIVE / GAMEPLAY CONTEXT

从地下车库入口到车外短距离；此轮只借最少空间回答操作问题。不表达完整家庭关系，不安排母亲/信件/异常叙事。

## MINIMUM IMPLEMENTATION

计划路径（当前均未创建）：pocs/stylized_3d/c0/project.godot（输入/入口），garage.tscn（灰盒节点与碰撞），garage.gd（静态类型、局部人物/车控制及镜头），spatial_smoke.gd（相关 SceneTree 输入流程探针），README.md（版本、启动与操作）。结果写 docs/pocs/RB-C0-001_REPORT.md；路径均相对此库。

键盘方案是实现提案：WASD 移动/低速驾驶、E 就近开关门/检查/上下车、R 重置、Esc 退出；按距离与朝向明确当前目标，先核冲突并在入口显示实际操作。门的碰撞随开关状态变化，不能靠检查标记放行。一个入口/主场景、一个检查位置，不建物品、菜单框架、资源经济。门关闭不能穿越；检查不是发动前置。可直接验证早上车、先绕车等合理路径。

范围预算：一轮最小实验，五个问题可试后仅做一次有限空间调整；持续失效即提交反例。记录实际投入；不接受原 30h 总包，不偷偷增加新阶段。

## WHY NOT LESS

静态图不能揭露遮挡、门槛卡住、镜头方向与移动冲突或切换时丢输入。方块与胶囊已足够；母亲动画、家庭道具、异常材质和正式资产对这五个问题没有必要。

## LEGACY DEPENDENCY

NONE。可参照输入/失焦经验，不复制旧框架、工程、模块、插件、资产或测试套件。

## 全局约束

C0 不含正式对白、家庭物件、异常美术、母亲完整动画；不建立 EventBus/QuestService/Inventory/GameState 底座。不增加插件、网络/遥测、付费工具。合理行动无剧情顺序锁，观察不改变机械状态。C0 通过不批准 C1 或 C 获胜。
